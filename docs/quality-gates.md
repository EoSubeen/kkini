# 품질 게이트

구현 스택이 생성되면 아래 명령을 실제 `package.json` 스크립트와 CI에 연결한다. 명령이 존재하지 않는 상태를 성공으로 취급하지 않는다.

## Pull Request 게이트

1. 포맷과 린트
2. TypeScript 타입 검사
3. 금융 계산 단위·회귀 테스트
4. Supabase 마이그레이션 및 RLS 정책 테스트
5. API 통합 테스트
6. 프로덕션 빌드

## 배포 게이트

- 회원가입 → 로그인 → 정보 입력 → 진단 → 레시피 → 점검 저장
- 로그아웃 → 재로그인 → 저장 결과 복원
- 사용자 A가 사용자 B 데이터에 접근하지 못함
- 김샌드 고정 사례 계산값과 계산 근거 일치
- 390px 모바일 화면에서 핵심 경로의 잘림·가로 스크롤 없음
- 프리뷰 환경에서 오류 로그와 네트워크 실패 확인
- 환경변수와 비밀키 스캔 통과

## 증거 형식

각 완료 보고에는 다음을 포함한다.

- 실행한 명령과 종료 코드
- 테스트 개수와 실패 개수
- 마이그레이션 버전
- 프리뷰 URL 또는 로컬 재현 절차
- 알려진 제한과 롤백 방법

## 금융 서비스 추가 점검

- 설명 문구와 계산식의 단위·기간이 일치한다.
- 반올림이 중간 단계가 아닌 계약된 단계에서 수행된다.
- 통계·제도값의 기준일과 출처를 표시한다.
- 모의계산 및 교육 목적 고지가 결과와 계산 근거 화면에 유지된다.
